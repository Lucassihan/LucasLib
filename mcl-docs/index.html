LucasLib · Monte Carlo Localization

The MCL module, documented

A particle filter that rides on top of LucasLib's odometry: it keeps 400 guesses of where the robot is, weights them against the field walls using the 4 distance sensors, and gently corrects chassis — so every existing movement function silently runs on a self-correcting pose. This is the implementation reference: every step, every knob, every small detail, and the full testing story.

400 particles 4 distance sensors → walls heading from resolveHeading blends into chassis at 0.35
The one-sentence model

track() already computes how far the robot moved each cycle; MCL takes that motion, predicts where 400 particles go, checks each against what the distance sensors should read from there, keeps the survivors, and nudges chassis.x/y toward their average. Heading is never touched — resolveHeading owns it.

The data flow

Odometry writes the pose fast; MCL corrects it a few times a second. The Pipeline page walks every box in detail.

Turning it on

// in your autonomous routine, after you set the starting pose:
chassis.setPos(-48, -60, 90);
StartMCL(-48, -60);          // seed the cloud at the known start (call again after any setPos)

// the mclTask is already running (launched in startTasks); it idles until StartMCL.
// from here on, driveTo / boomerang / etc. read a self-correcting chassis. Nothing else changes.auton.cpp
Before you trust it on the robot

It's validated in simulation only. You must, in Config & Tuning: ① measure the 4 sensor mounts, ② calibrate SENSOR_SCALE, ③ measure SIDE_PUSH_FORCE (N) and ROBOT_WEIGHT (kg), and ④ run the map test (expected vs. measured per sensor) first. Wrong mounts or a flipped angle convention make the filter converge confidently to a wrong pose.
